# §124 CAL: a local 35B MoE and a hosted model both clear the nine original tasks on attempt 1; the four harder ones split them

> Excerpt of §124 of a private lab notebook; paths, service names and hosts are generalised. The numbers are as
> measured. They come from the lab's original code-generation harness, of which `tests/cal/run.py` is the
> portable port (same tasks, same prompts and protocol; the port was verified by running every gold module
> through the tests, not by re-running these models). Treat the rows as the lab's, n=1 each.

**Setup.** 13 tasks: nine original calendar helpers plus expandRecurrence, buildIcs, layoutWeekSpans and
findFreeSlots. Thinking off, 4500 output tokens, up to 4 attempts, a same-model critic diagnosing failures,
borrowed (gold) dependencies for tasks that import another task's module. The local model ran on a llama.cpp
server at ctx 32768 (earlier rows used 16384; prompts are 3-5k tokens, so this should not matter, but it is
stated). The hosted model ran through an OpenAI-compatible cloud endpoint.

| task | Qwen3.6-35B-A3B (local) | DeepSeek-V4.1-flash (hosted) |
|---|---|---|
| nine original tasks | 9/9, attempt 1 | 9/9, attempt 1 |
| expandRecurrence (29 tests) | failed 12/29 | failed 28/29 |
| buildIcs (20) | failed 19/20 | passed, attempt 3 |
| layoutWeekSpans (23) | failed 22/23 | passed, attempt 1 |
| findFreeSlots (28) | failed 22/28 | passed, attempt 4 |
| total | **9/13** | **12/13** |

**Reading it.** Both clear the nine originals first try, so on the old set they are indistinguishable; the
four harder tasks are what separates them. The local model fails all four with most tests failing, the hosted
one passes three, two of them only after critic repairs.

**Caveats.**
- n=1 per model. The first-attempt column is the clean number; the final column depends on the critic.
- The local run took 4.9 h wall (the hosted one about 3.5 min). Its tokens/s slowed from ~11 to ~2 over the run
  while other disk and network jobs were running on the same host; the cause was not established, so
  **throughput for the last four tasks is not published**, only pass/fail.
- expandRecurrence on the hosted run shows zero critic calls over four attempts (dependency handling,
  unconfirmed), so its 28/29 failure is not a clean read of the model.
- Do not quote a 13-task total next to the earlier /9 rows.
